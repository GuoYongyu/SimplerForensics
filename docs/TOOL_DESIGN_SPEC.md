# SimplerForensics 工具设计规范

本文规定新增工具和改造现有工具时应遵循的产品、界面与实现约定。项目定位为本地优先、离线可用、模块独立的电子数据取证辅助工具集。

## 产品原则

- 每个工具聚焦一个清楚、可独立完成的任务；工具之间通过导航互相访问，不要求先建立案件或账户。
- 默认只读取用户选择的文件。需要转换或修复时，明确提示会生成派生副本，绝不覆盖输入文件。
- 文件和结果默认仅在本机处理。调用本地服务、命令行程序或外部资源时，页面须说明处理边界；不得静默上传用户文件。
- 将直接观察到的字段、计算结果、启发式线索和人工解释分开呈现。避免将线索描述成事实或结论。
- 说明支持的格式、已知限制、文件大小上限、时区或编码假设，以及失败时用户可以采取的下一步。

## 工具分类

首页与页内导航按用途分组：文件分析、移动设备与媒体、数据处理、系统与资料检索。新增工具只归入最贴近其主要任务的一组；首页卡片需提供名称、主要输入、核心输出及限制提示。

## 页面结构

每个独立页面采用以下顺序：

1. 共用顶栏、返回工具首页的面包屑、共用页内导航。
2. 页面标题、简短用途说明、主要格式或处理方式标签。
3. 输入区：文件工具支持文件选择；适用时支持拖放。输入区说明本地处理范围和支持格式。
4. 结果区：先显示状态与摘要，再显示字段、字节偏移或详细输出；长结果应可折叠或分段。
5. 适用范围与检测边界，说明解析失败、部分解析、编码或版本差异。

使用 `assets/style.css` 中的 `page-shell`、`breadcrumbs`、`page-heading`、`panel`、`drop-zone`、`field`、`button-row`、`status`、`result-box`、`table-wrap` 和 `tool-footer` 等共享样式。新增页必须加入 `assets/nav.js` 分组导航，并从首页对应分类链接。

## 交互约定

- 所有按钮使用 `type="button"`；输入均有可见标签，状态区使用 `role="status"` 与 `aria-live="polite"`。
- 文件输入应提供选择按钮、拖放反馈、文件名与大小；新选文件时清理旧结果与旧对象 URL。
- 状态统一使用 `status`、`status success`、`status warning`、`status error`；长任务提供进行中状态。
- 清空、重置、复制、下载等操作应给出可读反馈。复制失败时保留可手动选择的结果。
- 支持键盘操作、明显的焦点样式、窄屏布局和减少动态效果设置；重要信息不得只用颜色表达。

## 取证结果表达

- 文件原始字节或字段须与解析器推导值分开标识。
- 对二进制字段尽量显示来源位置、偏移（十进制与十六进制）、字节长度和字节序。
- 时间值注明原始字符串/数值、解释时区及转换结果；无法判断的时区应标记为未知。
- 解析器异常、数据截断、格式不支持、搜索限制和部分结果都应显式显示，不得静默忽略。
- 每项统计或启发式分析附带样本范围和限制；不得把未命中描述为“确认不存在”。

## 性能与文件安全

- 大文件按需分块读取，避免把完整文件及多份副本同时载入内存。
- 可能长于短交互的 CPU 密集型解析、扫描或解压任务优先放入 Web Worker；适合分块调度的任务可在主线程按块让出控制。两种方式都应提供可解释的进度、取消和过期结果清理机制。
- 对解压、递归容器和文本解析设置可解释的资源上限，并在达到上限时报告部分结果。
- 使用 `textContent` 或经过转义的输出渲染文件名、元数据和文件内容；不执行证据文件中的脚本或链接。
- 生成副本时使用新文件名，说明改动范围，并撤销不再使用的对象 URL。

## 实现约定

- 延续原生 HTML、CSS 和 JavaScript；默认不引入构建步骤、远程脚本、字体或运行时 API。
- 页面文件置于以工具命名的独立目录，通常包含 `index.html` 与 `app.js`；有专属样式或 Worker 时再增加文件。
- 共用导航、页面样式和通用逻辑放在 `assets/`，不要复制后各自分叉。
- 工具代码应将格式识别、解析、展示和交互分层；边界条件与错误路径需能从界面理解。
- 仅在确有必要时使用本机服务端接口，并为请求限制大小与时长、清理临时文件、避免把临时数据持久化。

## 发布前检查

- 从首页和页内导航都能到达新工具；标题、描述、支持格式和检测边界彼此一致。
- 文件选择、拖放、清空、重复选择、格式错误、截断文件、最大限制和窄屏布局均可正常处理。
- 原文件保持不变；所有导出都是用户明确触发的副本。
- 大任务可取消，取消后不会更新过期结果或遗留对象 URL、Worker 与临时状态。
- 页面在断网情况下可使用；没有新增未说明的文件外传路径。
