01命令结构与基本工作流入门

HashCat 是离线的哈希恢复工具：它不会“解密”哈希，而是不断生成候选明文、计算哈希并与目标比较。一条命令至少需要三部分：哈希模式（-m）、攻击模式（-a）和候选来源（字典或掩码）。

hashcat -m <哈希模式> -a <攻击模式> hash.txt [字典或掩码]
  • hash.txt：每行一个目标哈希；也可以直接把哈希写在命令行里。
  • -m：目标哈希算法，例如 MD5 是 0、SHA-256 是 1400。模式选错通常表现为 Token length exception 或永远跑不出结果。
  • -a：攻击模式，0 是字典、3 是掩码、6/7 是混合。
  • 破解成功后，HashCat 默认把结果写入当前目录的 hashcat.potfile；再次运行前可用 --show 查看已有结果。
# MD5 + 字典
hashcat -m 0 -a 0 hash.txt rockyou.txt

# MD5 + 掩码：6 位小写字母 + 2 位数字
hashcat -m 0 -a 3 hash.txt '?l?l?l?l?l?l?d?d'

# 查看已破解结果
hashcat -m 0 hash.txt --show

# 查看尚未破解的哈希
hashcat -m 0 hash.txt --left

本页是浏览器端的候选生成与验证工具，不是 HashCat 的前端；它不能调用 GPU，也不会执行你复制的命令。浏览器适合小空间、字典和规则验证，真正的 HashCat 在 GPU 上通常快几个数量级。更多规则、模式与示例见 hashcat wiki。

02哈希模式 -m：先选对算法必读

先用文件类型、来源系统或哈希长度判断算法；不确定时用 hashcat -hh 搜索模式，或使用 hashid 等辅助工具。常见模式如下：

-m算法说明

1400SHA-25664 位十六进制，无 salt
1700SHA-512128 位十六进制，无 salt

3200bcrypt$2a$ / $2b$ / $2y$，成本越高越慢

# 查看某个模式的示例哈希和格式
hashcat --example-hashes -m 3200

# 在完整帮助中搜索模式（-hh 会列出哈希模式）
hashcat -hh | grep -i -E 'sha256|ntlm|bcrypt'

本页只处理无 salt 的 MD5 / SHA-1 / SHA-256 / SHA-512 / NTLM 和 bcrypt。带 salt、WPA、Kerberos 等模式请使用完整 HashCat，并在教程对应位置查阅格式。

03攻击模式 -a：字典、组合、掩码与混合核心
-a模式候选来源典型用途
0Straight（字典）一个字典文件，可加规则常见密码、泄露字典、规则变形
1Combination（组合）两个字典逐词拼接姓 + 名、词 + 词
3Brute-force / Mask掩码已知长度与字符范围
6Hybrid Wordlist + Mask字典词 + 掩码后缀admin00、password2024
7Hybrid Mask + Wordlist掩码前缀 + 字典词2024admin、!password
 
# 字典
hashcat -m 0 -a 0 hash.txt dict.txt

# 字典 + best64 规则
hashcat -m 0 -a 0 hash.txt dict.txt -r rules/best64.rule

# 两个字典组合：left.txt 的每个词拼接 right.txt 的每个词
hashcat -m 0 -a 1 hash.txt left.txt right.txt

# 掩码：1 位大写 + 4 位小写 + 2 位数字
hashcat -m 0 -a 3 hash.txt '?u?l?l?l?l?d?d'

# 混合：字典词 + 2 位数字后缀
hashcat -m 0 -a 6 hash.txt dict.txt '?d?d'

# 混合：2 位数字前缀 + 字典词
hashcat -m 0 -a 7 hash.txt '?d?d' dict.txt

选择顺序通常是从低成本到高成本：先字典 + 常用规则，再针对已知结构用掩码或混合，最后才考虑扩大掩码空间。每次运行前先确认 --show 是否已有结果。

04掩码语法与自定义字符集-a 3

掩码按位置描述字符集合。每个 ? 标记占一个位置；字面问号写成 ??。在 shell 中建议用单引号包住掩码，避免 ? 被通配符展开。

标记字符集说明
?la–z26 个小写字母
?uA–Z26 个大写字母
?d0–910 个数字
?s空格与标点常见特殊字符
?a?l + ?u + ?d + ?s全部 95 个可打印 ASCII 字符
?b0x00–0xff原始字节；本页不支持
?h / ?H0–9a–f / 0–9A–F十六进制字符
?1–?4自定义配合 -1–-4 定义
 
# 8 位小写字母
hashcat -m 0 -a 3 hash.txt '?l?l?l?l?l?l?l?l'

# 4 位小写 + 2 位数字
hashcat -m 0 -a 3 hash.txt '?l?l?l?l?d?d'

# 自定义字符集 1 = 小写 + 数字，重复 8 位
hashcat -m 0 -a 3 -1 '?l?d' hash.txt '?1?1?1?1?1?1?1?1'

# 两个自定义字符集：4 位字母 + 2 位数字
hashcat -m 0 -a 3 -1 '?l' -2 '?d' hash.txt '?1?1?1?1?2?2'

# 手机号：1 开头 + 10 位数字
hashcat -m 0 -a 3 hash.txt '1?d?d?d?d?d?d?d?d?d?d'

# 只预览生成的候选，不计算哈希
hashcat -a 3 --stdout '?l?l?d' | head

掩码不表达“分支”。例如年份 19xx 或 20xx 需要分别运行两次，或使用 -a 6 把年份放进字典。递增长度可用 -i：

# 尝试 4–8 位小写字母，长度递增
hashcat -m 0 -a 3 -i --increment-min 4 --increment-max 8 hash.txt '?l?l?l?l?l?l?l?l'

# 估算掩码空间（不计算哈希）
hashcat --keyspace -a 3 '?l?l?l?l?d?d'

本页的“可视化构建器”会把块编译成同样的掩码；自定义字符集支持 ?l?d 这样的写法。候选空间会随位数指数增长，浏览器请优先缩小范围。

05字典、规则与混合攻击-a 0 / 6 / 7

字典攻击把文件里的每一行当作候选明文。规则（rules）在不改变字典文件的情况下，对每个词做变形，例如转小写、首字母大写、追加数字、替换字符。HashCat 自带 rules/ 目录，常见的有 best64.rule、dive.rule、rockyou-30000.rule。

规则含义示例（password →）
:不做变换password
l全部小写password
u全部大写PASSWORD
c首字母大写，其余小写Password
r反转drowssap
d重复一次passwordpassword
$1末尾追加字符 1password1
^1开头插入字符 11password
sa@把所有 a 替换成 @p@ssword
se3把所有 e 替换成 3pass3rd
so0把所有 o 替换成 0passw0rd
ss$把所有 s 替换成 $pa$$word
@a删除所有 apssword
[ / ]删除首字符 / 尾字符assword / passwor

p2末尾再追加 2 份当前词（共 3 份）passwordpasswordpassword
 
# 字典 + best64 规则
hashcat -m 0 -a 0 hash.txt dict.txt -r rules/best64.rule

# 多个 -r 规则文件会做组合，而不是简单串联
hashcat -m 0 -a 0 hash.txt dict.txt -r rules/best64.rule -r rules/toggles1.rule

# 只预览规则生成的候选
hashcat -a 0 --stdout dict.txt -r rules/best64.rule | head

# 把候选导出为文件，供其他工具或本页使用
hashcat -a 0 --stdout dict.txt -r rules/best64.rule > candidates.txt

# 混合：词 + 2 位数字
hashcat -m 0 -a 6 hash.txt dict.txt '?d?d'

# 混合：2 位数字 + 词
hashcat -m 0 -a 7 hash.txt '?d?d' dict.txt

本页的规则是可视化近似：基础变换、反转、重复、1337、前后缀、追加字符和年份。它不复刻 HashCat 的全部规则语法；需要精确复现时，请使用 -r 规则文件。

07结果管理、potfile 与恢复运维

HashCat 默认把成功结果写入 hashcat.potfile。这是一份明文记录，可能包含敏感信息；在共享机器上应指定私有路径或及时清理。默认情况下，同一个哈希再次运行会直接跳过，因为 potfile 已记录。

# 指定 potfile 与输出文件
hashcat -m 0 -a 0 hash.txt dict.txt --potfile-path ./case.potfile -o cracked.txt

# 查看某个 potfile 中的结果
hashcat -m 0 hash.txt --show --potfile-path ./case.potfile

# 临时忽略 potfile（不读取也不写入）
hashcat -m 0 -a 0 hash.txt dict.txt --potfile-disable

# 恢复上次中断的命名会话
hashcat --restore --session myrun

# 将已破解结果输出为纯文本（格式 2 = plain）
hashcat -m 0 hash.txt --show --outfile-format=2 --outfile results.txt

# 较新版本也支持 JSON 输出；以本机 hashcat --help 为准
hashcat -m 0 hash.txt --show --outfile-json --outfile results.json

--remove 会从哈希文件中删除已破解行，属于破坏性操作；先复制一份原始文件。不要把 potfile、字典或结果上传到不可信位置。

08性能、硬件与推荐工作流效率

HashCat 的核心优势是把大量候选并行交给 GPU。CPU 也能跑，但速度通常低几个数量级。影响速度的主要因素：哈希算法、GPU 型号、驱动/OpenCL 运行时、-w 工作负载、规则复杂度、掩码长度和候选空间。

  • 先 hashcat -b -m <模式> 测实际速度，再决定候选空间是否现实。
  • 从字典 + best64 开始；再针对已知结构做混合攻击。
  • 掩码每增加一位，空间乘以字符集大小；优先缩小字符集，而不是盲目加长。
  • 长任务使用 --session 与 --restore，并定期用 --show 检查结果。
  • bcrypt、WPA、Kerberos 等高成本模式需要更多算力；先评估是否值得。
# 推荐的最小工作流
hashcat --show -m 0 hash.txt
hashcat -b -m 0
hashcat -m 0 -a 0 hash.txt dict.txt -r rules/best64.rule --status --status-timer=5
hashcat -m 0 -a 6 hash.txt dict.txt '?d?d' --status
hashcat -m 0 hash.txt --show

浏览器的 Web Crypto 和 Web Worker 适合验证小规模候选，但没有 GPU 加速。同样的候选空间，真正的 HashCat 可能只需几秒到几分钟，而本页可能需要很久；请以“小空间、字典、已知结构”为主。

10常见错误与合法使用排错

OpenCL/驱动报错驱动、运行时或设备选择问题用 -I 查看设备；更新驱动；必要时再考虑 --force

合法与安全：只对你有权测试的哈希使用破解工具，例如自己的账户、授权渗透测试、离线取证或 CTF。不要用它尝试登录他人系统、绕过访问控制或处理来源不明的数据。HashCat 是离线工具；对在线服务的暴力尝试既低效也可能违法。妥善保护哈希、字典、potfile 和结果文件。

适用范围与边界

本页支持

  • 无 salt 的 MD5、SHA-1、SHA-256、SHA-512、NTLM 和 bcrypt 验证。
  • 掩码、字典 + 规则、字典/掩码混合、正则子集生成。
  • 长度、字符类型、必须包含/排除等候选过滤。
  • 本地 Web Worker 并行；可随时停止；结果可复制或导出。

不支持

  • 带 salt、WPA、Kerberos、NetNTLM 等需要额外字段的模式。
  • HashCat 的完整规则语法、?b 原始字节、GPU/OpenCL、分布式破解。
  • 环视、反向引用、Unicode 属性类等正则特性。
  • 候选按 UTF-8 文本处理；非 ASCII 字符与 HashCat 的原始字节掩码可能有差异。
  • 超过 5 亿个候选的掩码/正则空间；混合和字典没有固定上限，但会边读边跑。

安全边界

  • 哈希、字典、候选和结果只在本页内存中处理，不上传、不写入服务器。
  • 不读取未选择的本地文件；不生成 potfile；只有点击复制/导出才会产生副本。
  • 页面可离线使用；没有远程脚本、字体或 API。

HashCat 是其作者的项目名称；本页是 SimplerForensics 的浏览器端独立实现，不是官方前端，也不包含 HashCat 二进制。仅用于你拥有或获授权的哈希。如果只需要简单的本地字典匹配，也可以使用 密文字典匹配。
